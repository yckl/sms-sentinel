## 过程中发现并修复的问题

1. **Android 15 禁止“无全屏 Intent 的 CallStyle”**
   - 现象：禁用全屏权限后，`NotificationCompat.CallStyle` 通知抛出
     `IllegalArgumentException: CallStyle notifications must be for a foreground service or user initiated job or use a fullScreenIntent`，接收器进程崩溃。
   - 处理：`allowFullScreen == true` 时才使用 CallStyle；否则改用 `BigTextStyle` + 接听/挂断动作的高优先级通知。中文动作标签也随之生效。

2. **Android 15 edge-to-edge 压住状态栏**
   - 现象：targetSdk 35 下权限页的“返回”按钮被状态栏覆盖。
   - 处理：新增 `util/Insets.kt`，在 MainActivity / PermissionActivity / IncomingCallActivity 统一应用系统栏 inset。

3. **底部导航图标被压成一条线**
   - 现象：`BottomNavigationView` 固定 76dp 高度时图标只剩 10px。
   - 处理：改为 `wrap_content` + `minHeight=80dp`，并用主题覆盖 `colorSurfaceContainer` / `colorSecondaryContainer`，去掉 Material3 默认的淡蓝底色。

4. **全屏来电上叠加通知**
   - 现象：全屏 Activity 已显示，CallStyle 通知仍以横幅覆盖在顶部。
   - 处理：`IncomingCallActivity` 启动后取消该任务的通知；`CallNotifier.show` 同时取消其他待确认任务的旧通知，避免多个全屏 Intent 竞争。

5. **通知在锁屏显示正文**
   - 现象：系统“锁屏显示所有通知内容”时，`VISIBILITY_PRIVATE` 的 publicVersion 不会生效，正文仍被展示。
   - 处理：通知正文默认固定为“重要短信待确认，点击查看全文”；只有用户在设置中显式开启“锁屏显示正文”时才显示原文。

6. **前台收到短信后首页不刷新**
   - 现象：广播创建任务后，首页仍显示 0 条。
   - 处理：`TaskStore` 暴露 `revision: MutableLiveData<Long>`，首页和记录页观察它并实时刷新。

## 设计文档与实现的差异

- 设计稿中的 CallStyle 降级在 Android 14+ 不能作为“无全屏 Intent”的通知样式使用；实现改为普通高优先级通知，视觉上不再是通话卡，但接听/挂断语义保持一致。
- 设计稿要求“通知摘要”，实现默认完全脱敏；这是出于锁屏隐私的保守选择，可在设置中开启“锁屏显示正文”。
- 多条短信聚合仍是 P1：当前为每条任务独立通知，触发新提醒时会取消其他旧通知，避免堆叠和错误的全屏 Intent。

# V1.1 变更（2026-10-20）

## 真机反馈与处理

用户反馈：真机上只有安装后第一次收到短信会弹来电，之后必须打开 App 才会弹。

处理：
1. 新增 `MonitoringService` 前台服务（`foregroundServiceType="specialUse"`），App 启动/开机/收到提醒时启动，持续显示一条低优先级“正在监听”通知，降低进程被厂商回收的概率。
2. `MainActivity.onStart` 每次启动服务；`BootReceiver` 在重启后恢复调度并尝试启动服务。
3. 权限页增加“后台监听服务：运行中/未运行”，可直接启动并查看状态。
4. 设置和权限页增加“厂商保活设置”指引：小米 HyperOS、OPPO、vivo、荣耀/华为、原生 Android 的自启动、后台运行、省电、锁屏通知路径。
5. 新增应用内顶部来电横幅：App 在前台时，新会议短信从顶部滑入，可直接接听/挂断，避免只依赖系统通知。
6. 说明：如果厂商仍然强制冻结或用户“强行停止”App，任何普通应用都无法保证短信广播一定送达；必须完成厂商白名单设置。

## 会议关键词过滤

用户反馈：一天十几条 OA 公文，不想每条都来电。

处理：
- 默认开启过滤，关键词 `会议,开会,参会,议程,会场`。
- 在“设置 → 短信过滤”可关闭过滤或编辑关键词（逗号分隔；清空关键词等于不过滤）。
- `SmsReceiver` 在号码匹配后、创建任务前检查正文关键词；非会议短信不生成任务、不响铃。
- 已用模拟器验证：非会议短信 0 条任务；会议短信生成 1 条任务并触发提醒。

## iOS 27 风格重做

- 配色改为 iOS 系统色：蓝 `#0A84FF`、绿 `#34C759`、红 `#FF3B30`、分组背景 `#F2F2F7`。
- 大标题、分组白卡、悬浮胶囊底栏、圆形接听/挂断按钮。
- 底栏改为自绘的三个 Tab（待处理/提醒记录/设置），避免 Material `BottomNavigationView` 在悬浮卡片里压扁图标。
- 应用图标使用用户提供的 `tubiaoui.png`，生成 mdpi–xxxhdpi 五套 PNG。
- 来电通知增加应用大图标；应用内顶部横幅使用同样的白色圆角卡片。
- Android 15 edge-to-edge 与状态栏 inset 已保留。

## V1.1 已验证

- 关键词过滤：非会议短信不生成任务；会议短信生成任务并提醒。
- 前台服务：`dumpsys activity services` 显示 `isForeground=true`，通知渠道 `sentinel_monitor`。
- 后台锁屏：短信到达后 `IncomingCallActivity` 全屏拉起，正文隐藏。
- 应用内顶部横幅：通知权限关闭时仍能在首页顶部弹出接听/挂断卡片。
- 自定义底栏：三个 Tab 可切换，图标不再压扁。
- 仍然是 debug 签名，未做真机厂商适配与 release 签名。

# V1.2 修复（2026-10-20）

## 震动

- 原实现把震动和声音一起受“勿扰/中断过滤器”限制，导致静音或勿扰时不震动。
- 现在声音继续遵循系统静音/勿扰；**震动改为直接调用 Vibrator，不受静音/勿扰限制**。
- 短信到达和循环提醒时额外触发一次短震动，作为通知/全屏被厂商拦截时的兜底。
- App 前台顶部横幅也会震动；短震动做了 1 秒去重，避免重复触发。
- 设置里的“震动反馈”开关打开时会立即测试震动，没有马达时提示。

## 锁屏唤醒

- 锁屏通知不再固定使用静音通道；即使全屏页面被厂商拦截，通知本身也会响铃/震动。
- `IncomingCallActivity` 增加 `SCREEN_BRIGHT_WAKE_LOCK | ACQUIRE_CAUSES_WAKEUP`，配合 `setTurnScreenOn` 提高锁屏亮屏成功率。
- 首页在缺少通知权限或全屏特殊访问时显示橙色警告卡和“去开启”按钮。
- 权限页新增“锁屏唤醒测试（8 秒后）”：点击后立即锁屏，8 秒后应出现全屏来电，用于区分“App 没收到”与“厂商拦截了唤醒”。

## 通知小窗按钮

- 亮屏使用中不再使用 CallStyle，改为普通高优先级通知，明确显示“挂断确认 / 接听查看”两个中文按钮。
- “挂断确认”走广播 `DeclineReceiver`，直接在后台把任务标记为“已确认 · 未阅读”，并提示“已确认（未阅读）”，不打开 App。
- 只有“接听查看”才进入 App 详情页；锁屏时仍优先全屏来电。

## V1.2 已验证（模拟器）

- 锁屏全屏来电；震动服务记录显示 App 持续震动 60 秒。
- 静音/勿扰逻辑：震动不再依赖中断过滤器。
- 解锁状态通知两个中文按钮；点“挂断确认”后任务状态变为 `CONFIRMED_UNREAD`，Activity 仍是 MainActivity，没有跳转。
- 锁屏唤醒测试：8 秒后屏幕点亮并拉起 `IncomingCallActivity`。
- 关闭全屏特殊访问后，首页出现“全屏来电未授权，锁屏可能不会唤醒”警告。

# V1.3.1 修复（2026-10-20）

- 问题：打开“保持后台监听”后，下面的“后台监听服务”仍显示“未运行”，必须再点那行才变成“运行中”。
- 原因：服务启动是异步的，开关回调里的界面刷新早于 Service.onStartCommand。
- 修复：`MonitoringService` 增加 `runningLive` 可观察状态，并在 `start()` 时乐观置为运行；设置页和权限页观察该状态实时刷新。启动异常时自动回退为“未运行”。
- 已验证：关闭开关显示“未运行”；重新打开后无需点击服务行，立即显示“运行中”。

# V1.3.2 震动诊断（2026-10-20）

- 震动改为 `USAGE_ALARM`（Android 13+ 用 VibrationAttributes，旧版本用 AudioAttributes），比普通通知震动更容易在静音/勿扰下保留。
- 设置页新增“测试震动”行：点击会强制测试震动，并自动打开已关闭的“震动反馈”。
- 如果测试仍无感觉，提示检查系统“静音时振动 / 触感反馈 / 震动强度”，以及是否处于省电模式。
- 模拟器验证：测试震动记录 usage=ALARM；短信到达和全屏来电也走同一震动通道。

# V1.3.3 解锁来电式通知（2026-10-20）

- 解锁状态也使用 CallStyle 来电通知，带有通话类通知的常驻/置顶属性，不再只是普通会话通知。
- 通知渠道改为静音，铃声和震动由常驻前台服务统一负责整个振铃时长（默认 60 秒），避免通知渠道的震动把持续震动顶掉。
- 全屏来电页启动后会同步停止服务铃声并接管震动；加入 `alertSuppressed` 防止服务与页面互相取消震动。
- 同一时间只保留一个来电通知，避免多条通知互相覆盖。
- 已验证：解锁时 CallStyle 通知常驻、服务持续震动；锁屏时全屏页接管后仍持续震动。

# V1.4.0 系统级悬浮来电胶囊（2026-10-20）

- 新增 `SYSTEM_ALERT_WINDOW` 悬浮窗，解锁状态下无论当前在桌面、微信还是其他 App，都从屏幕顶部弹出常驻来电胶囊。
- 胶囊包含来源/条数、短信摘要、挂断（确认未阅读）和接听（打开详情）两个按钮。
- 同一时间只保留一个胶囊；新短信到来时更新内容与条数，不会叠出多个。
- 振铃结束后胶囊继续常驻，直到用户接听/挂断；锁屏仍走全屏来电页。
- 横竖屏通过 `onConfigurationChanged` 重新计算宽高与位置。
- 权限页新增“悬浮来电横幅”，首页缺少权限时显示“悬浮来电未授权”警告。
- 修正：停止提醒/隐藏胶囊按任务 ID 精确匹配，避免旧任务的全屏页误关新任务的胶囊。
- 已验证：桌面状态下悬浮胶囊弹出并常驻、点击挂断后任务变为 `CONFIRMED_UNREAD`、新短信更新同一胶囊、锁屏全屏页接管后持续震动。
